# GURU AI Technologies — Website

Static HTML + vanilla JS + CSS site on **Cloudflare Pages**, with Pages Functions for the
**GURU AI — Intelligent Business Assistant** (`/api/chat`) and project-lead capture (`/api/leads`, D1).
No React / Next.js / framework. 254 HTML pages, 73 indexable (see `docs/SEO-IMPLEMENTATION.md`).

## Quick start
```bash
npm i -D wrangler            # once
cp .dev.vars.example .dev.vars   # fill with YOUR keys; never commit
npm run db:migrate:local
npm run dev                  # http://localhost:8788
npm run check                # site validation (SEO, links, JSON-LD)
npm test                     # API integration tests (mock AI/email/Turnstile, real local D1)
```
The site works with **no** keys: the chatbot falls back to the rule-based engine and the lead
endpoint answers 503 (the UI then shows the verified WhatsApp/email contacts instead of claiming a submission).

## Layout
| Path | Purpose |
|---|---|
| `*.html`, `services/`, `industries/`, `case-studies/`, `legal/` | pages |
| `style.css`, `site-nav.*`, `homepage-*.{css,js}` | site styling / behaviour |
| `chatbot/` | client chatbot sources; `chatbot.bundle.js` is generated by `scripts/build-chatbot.mjs` |
| `functions/api/{chat,leads,config}.js`, `functions/api/admin/leads.js` | Pages Functions |
| `functions/_lib/` | http, validation, rate limit, Turnstile, email, retrieval, prompt, LLM client |
| `functions/_kb/kb.json` | generated retrieval knowledge base (`npm run build:kb`) |
| `knowledge/*.json` | curated, verified business facts feeding the KB |
| `migrations/` | D1 schema |
| `scripts/` | build/validate tools |
| `tests/` | API tests + crawler |
| `docs/` | all documentation and audits |

## Documentation

## Rebuild generated files
After editing `knowledge/`, page content or `chatbot/*.js`: `npm run build:kb && node scripts/build-chatbot.mjs`.
After adding/removing pages: `node scripts/build-sitemap.mjs && npm run check`.
